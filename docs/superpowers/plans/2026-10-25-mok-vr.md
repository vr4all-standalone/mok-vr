# The Maze of the Kings VR implementation plan

Goal: turn the existing MOK engine support into a standalone Quest and PC VR port matching the four delivered light-gun mods.

Architecture: inherit the released Lupin shared menu, input ownership and lifecycle code. Keep MOK's existing measured camera and staff extractor; give MOK its own media checks, identity and releases. Do not alter other mod repositories.

User scope: same workflow and features as the other four ports. Implementation choices: `E:\___flattovrdev\mok-vr`, `com.vrlightgunhub.mok`, version 1.0.0, stable filenames `mok-vr-quest.apk` and `mok-vr-pcvr.zip`. Preserve VR4ALL's existing `mok-vr` card and user mappings.

- [ ] Create isolated local checkout from the latest shared-menu Lupin revision; copy local build dependencies and licensed bundled models.
- [ ] Add and run failing standalone/media/setup tests. Implement MOK title gate, CHD/PIC checks and branded Android setup. Accept owned mok.zip + mok/gds-0022.chd and supported NAOMI BIOS.
- [ ] Verify inherited MOK staff extraction, cache reuse, corruption/skip recovery, stereo/widened view, menu persistence, solo hand transfer and both two-player layouts in the simulator. Fix demonstrated MOK-specific defects only; never infer native game state from another port.
- [ ] Adapt build/package validation, launcher, docs and visual assets. Build Windows and signed arm64 Quest; verify identities, source revision, licenses and exclusion of game files.
- [ ] Update existing VR4ALL card, download selection and device package mapping with regression checks. Keep upstream HOTD2 independent.
- [ ] Review the changes, prepare local PC folder and verify final artifacts. Publish matching GitHub source/releases and artwork within the established mod workflow; verify public assets and VR4ALL discovery.

Review focus: wrong game/disc must fail before Play; direct launch cannot bypass checks; held input must not leak across preparation/menu/join/layout changes; corrupt staff cache must not be accepted; public packages contain neither game files nor extracted models/signing secrets. Physical headset testing remains separate and must be reported accurately.

Progress: reconnaissance confirms the existing MOK profile and staff extractor are present in the latest Lupin base, and owned MOK files are available locally. The task is authorized as a continuation of the prior four ports; proceed without an extra design approval round.
